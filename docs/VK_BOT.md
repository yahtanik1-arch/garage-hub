# Бот GarageHub во ВКонтакте

**Коротко:** человек пишет сообществу GarageHub, выбирает бокс, дату и часы и отправляет заявку. Администратор подтверждает её или отказывает. Клиент получает результат в ВК и видит свои заявки в меню. ВК, Telegram и сайт используют одну базу: занять одни часы двум клиентам нельзя.

## Что реализовано

- Главное меню, `/start`, `/find`, `/my`, `/contacts`, `/id`, `/app`.
- Тот же пошаговый поиск, фильтры, карточки и фотографии, что в Telegram.
- Выбор даты и непрерывного диапазона часов, расчёт цены на сервере, создание заявки.
- Список своих заявок, карточка, карта, отмена с подтверждением.
- Форма «Разместить бокс» для владельца.
- Админка: новые заявки, подтверждение и отказ, расписание, заявки владельцев, создание/редактирование объектов, фотографии, архив и восстановление.
- `/client` и `/admin` для переключения режима администратора.
- Подтверждения, отказы и напоминания отправляются в мессенджер клиента. Администраторы обоих каналов видят общие заявки.
- Кнопка открытия использует существующее ядро доступа. В production реальные замки по-прежнему отключены; на локальном стенде работает имитатор.

Бронирование внутри ВК повторяет **Telegram-сценарий с подтверждением администратором**. Демонстрационная оплата публичного сайта остаётся отдельным сценарием. Настоящего эквайринга эта доработка не добавляет.

## Текущее состояние и граница проверки

Код и миграция подготовлены для подключения. Сообщество ВК ещё не создано, поэтому бот **не запущен в настоящем ВКонтакте**. Автоматические проверки используют настоящий локальный PostgreSQL/PostgREST и подменяют только внешние API. Они не заменяют проверку кнопок, загрузки фотографий и разрешений на сообщениях реального сообщества.

## Как подключить

1. Создать сообщество GarageHub и включить сообщения сообщества. В настройках сообщений включить возможности ботов/клавиатур, если интерфейс ВК предлагает отдельный переключатель.
2. В разделе работы с API создать **ключ сообщества** с правом на сообщения и фотографии. Пользовательский токен не нужен. Числовой ID сообщества записать в `VK_GROUP_ID`.
3. Сохранить ключ только в `/opt/garagehub/.env` на сервере. В GitHub и чат его не отправлять. Добавить:

   ```dotenv
   VK_GROUP_ID=123456789
   VK_GROUP_TOKEN=ключ_сообщества
   VK_CALLBACK_SECRET=случайная_строка_от_16_до_128_символов
   VK_CONFIRMATION_CODE=строка_подтверждения_из_настроек_Callback_API
   VK_ADMIN_IDS=
   VK_PORT=8083
   WEBSITE_URL=https://garagehub-176-53-244-150.sslip.io
   ```

   `VK_CALLBACK_SECRET` — отдельный случайный секрет из букв, цифр, `_` и `-`. Сгенерировать можно командой `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`. Тот же секрет указать в настройках Callback API **до подтверждения сервера**.

4. Создать backup рабочей базы, применить `sql/008_vk.sql` после миграций 000–007. Обновить код всех процессов, работающих с базой; миграция добавляет общую обработку аккаунтов ВК.
5. Убедиться, что системный пользователь `garagehub` может записывать фотографии в `/opt/garagehub/assets/garages`. Установить `deploy/garagehub-vk.service` в `/etc/systemd/system/` и добавить nginx-location из `deploy/nginx.selectel.conf.example`:

   ```nginx
   location = /vk/callback {
       proxy_pass http://127.0.0.1:8083;
       proxy_set_header Host $host;
       proxy_connect_timeout 3s;
       proxy_read_timeout 5s;
   }
   ```

   Запуск: `sudo systemctl daemon-reload`, затем `sudo systemctl enable --now garagehub-vk`. После `sudo nginx -t` перезагрузить конфигурацию nginx. Перезапустить `garagehub-worker`, `garagehub-web` и `garagehub-app`, чтобы они получили актуальный код и настройки.

6. В Callback API выбрать версию **5.199**, адрес `https://garagehub-176-53-244-150.sslip.io/vk/callback`, секрет из `.env`. Подтвердить сервер. В событиях включить входящие сообщения (`message_new`) и действия с callback-кнопками (`message_event`). Long Poll для этой реализации не нужен.
7. Написать сообществу `/id`. Положительный VK ID из ответа добавить в `VK_ADMIN_IDS` и перезапустить процессы. Telegram ID в этот список не переносить: это разные аккаунты. Каждый администратор должен сначала написать сообществу, чтобы оно могло отправлять ему сообщения.

Дополнительный VPS не требуется. `python -m vkbot` слушает только `127.0.0.1:8083`. Общая очередь уведомлений обслуживается `python -m core.worker`; он умеет работать с настроенным ВК и без Telegram-токена. Если у старых фотографий есть только Telegram `file_id`, для их переноса в ВК нужен существующий Telegram-токен/прокси; локальные фотографии и новые фото ВК от Telegram не зависят.

## Как это устроено в коде

- `vkbot/client.py`: HTTP API ВК, перевод клавиатур и HTML-текстов, загрузка фото.
- `vkbot/transport.py`: преобразование проверенных событий ВК в формат уже установленного диспетчера aiogram. Он используется как движок сценариев и состояний; сами сообщения уходят через HTTP API ВК.
- `vkbot/webhook.py`: проверка сообщества и секрета, сохранение события в базе, обработка очереди.
- `vkbot/__main__.py`: отдельный HTTP-процесс и напоминания для клиентов ВК.
- `core/service.py`, `core/db.py`, `core/locks.py`: общие правила, транзакции и доступ к боксам.
- `sql/008_vk.sql`: отдельный VK ID, очередь входящих событий, изоляция каналов и общие права доступа.

### Аккаунты и права

В таблице броней Telegram ID хранится в `client_telegram_id`, VK ID — в `client_vk_id`. Заполнить оба одновременно нельзя. Для внутренних блокировок, аудита, очередей и прав доступа ключ Telegram положительный, ключ ВК — отрицательный. Например, Telegram `700` и VK `700` — разные ключи `700` и `-700`. Отрицательный ключ никогда не отправляется в Telegram: транспорт направляет его в ВК с исходным положительным ID.

Это **не связывание аккаунтов**. Брони одного человека из Telegram автоматически не появляются в его аккаунте ВК. Брони с публичного сайта не становятся доступными по совпадению номера телефона или ID. Настройка `VK_ADMIN_IDS` не выдаёт права одноимённым Telegram-пользователям.

### Повторная доставка и сбои

Webhook отвечает `ok` после сохранения события в `vk_events`, а не после всех запросов к ВК. Одинаковые `group_id + event_id` сохраняются один раз. Секрет Callback API в таблицу не записывается. После успешной обработки текст события удаляется, остаётся служебная отметка для защиты от повторов. События одного пользователя обрабатываются по порядку; неудачная попытка не позволяет следующему ответу попасть в чужой шаг формы. Обработчик очереди повторяет неудачные попытки; при остановке во время работы событие остаётся в базе до окончания аренды на обработку (до пяти минут).

Создание брони имеет отдельный постоянный ключ события. Если запись уже сохранена, а отправка ответа оборвалась, повтор показывает существующую бронь. Исходящие сообщения получают стабильный `random_id` для повторов. При этом не обещается «ровно один раз» для всей переписки или произвольного административного действия: изменение базы и внешний API не являются одной транзакцией.

Пошаговая форма, как и в существующем Telegram-боте, хранится в памяти одного процесса. После перезапуска незавершённый выбор может потребовать `/start`; сохранённые заявки остаются в базе. Запускать несколько экземпляров VK-процесса для одного сообщества нельзя. Длинные списки клавиш разбиваются на несколько сообщений с учётом ограничений ВК; кнопки не отбрасываются. Телефон в форме владельца вводится текстом: Telegram-кнопки передачи контакта у ВК нет.

## Проверки перед включением для клиентов

Отправить `/start` и `/id`, пройти поиск и создать заявку, подтвердить её из Telegram и получить результат в ВК. Проверить отказ, отмену, напоминание и карту. Убедиться, что обычный пользователь не открывает админку, а одинаковые числовые ID в двух мессенджерах не видят чужие заявки. Администратору создать и отредактировать тестовый объект, загрузить фото, убрать его в архив и восстановить. Повторить проверку после перезапуска процесса.

Изолированные проверки: `python -m tools.local_db up`, затем `python -m tools.local_db test` из окружения проекта. Они не используют рабочую базу и не отправляют сообщения пользователям.
